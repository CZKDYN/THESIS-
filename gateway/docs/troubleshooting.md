# Troubleshooting and field integration checklist

Inspect `health` plus systemd/Mosquitto logs first. Share only fixed category/status lines with credentials hidden. Never paste `.env`, bearer tokens, broker passwords, unmasked Render environment settings, databases or private keys into chat/issues.

| Symptom | Diagnose and recover |
| --- | --- |
| No room data / broker disconnected | Check Pi service heartbeat, LAN link/Wi-Fi coverage, correct LAN IP/8883, certificate SAN/CA/expiry, and broker username/password/ACL. Anonymous/plaintext access must stay disabled. |
| Broker connected but room unknown/stale | Pi/broker online does not establish ESP32/PZEM availability. Check room power/network and firmware status heartbeat/LWT, sample age and UART diagnostics. Do not synthesize zero readings. |
| Delayed measurement received now | `last_received` is arrival; `last_measurement` is original sample time. Inspect backlog/cloud outage. Historical samples remain historical after upload. |
| `device_mapping_invalid` | Match registered device/unit IDs, topic and ACL independently. Stop that publisher, fix provisioning, retain its original invalid frames for review. Never relabel another room's recorded energy. |
| `device_clock_unsynchronized`, `timestamp_future` | Check actual ESP32 NTP/drift and Pi NTP. Preserve original times. Reject/quarantine uncertain firmware samples; do not label receipt time as sample time. |
| `ntp_not_synchronized`, `clock_jump_detected` | Verify `timedatectl`, network/NTP and host clock; upload pauses. Jumps require stabilization. Locally committed frames remain queued; do not modify them. |
| `blocked_auth` | Re-provision/rotate the correct scoped token, confirm device active and mapping. An archived unit is intentionally denied. Resume only the repaired alias. |
| `blocked_tariff` | The API cannot authorize a charge for that original interval. Confirm real utility source/period/coverage in the cloud with the owner. Do not invent an applicable rate, backdate a new tariff or move sample times. |
| `blocked_conflict` | Exact scoped receipt was missing/different. Compare the retained original against authorized server records. Newer accepted readings can make late packets unbillable through this API. The gateway retains them for an explicit accounting decision; no automated rewrite/delete is offered. |
| `blocked_retry` | Inspect cloud-path reachability, certificate verification, API health and queue length. Finite retry budget is exhausted; originals remain. Repair and deliberately resume the affected alias. |
| `storage_unavailable_no_ack` | Disk admission cutoff/full SD/SQLite I/O problem. Upstream firmware must keep originals. Make a verified backup/recovery copy, repair storage, inspect integrity, restart. Never delete unsent rows to make the error disappear. |
| `meter_reset_not_approved`, `counter_decreased` | Verify actual PZEM counter/history. Ordinary restart cannot generate a new epoch. A physical reset needs operator approval plus explicit new-epoch baseline. Keep uncertainty visible; do not infer missing kWh. |
| Another instance owns journal | Keep one run worker/systemd instance. Health/backup commands are separate SQLite clients; never start a second uploader for the same database. |
| Worker failed / repeated restart | Check fixed diagnostic category, secrets permissions, schema/integrity and disk reserve. systemd restarts on failure and limits rapid restarts. Preserve journal/backups before investigation. |
| Config changed but journal refused | Profile binding prevents mode/destination/mapping reuse. Preserve the old journal and reconcile it; use a new database for a distinct deployment. Token-file rotation alone is allowed. |

## Chronological integration checklist

1. Review the feature branch, API receipt/error additions, tests and adviser-approved scope. Merge/deploy the reviewed website change before a real gateway trial; verify receipt authentication without sending fabricated readings. Keep website simulation disabled and production mail/owner credentials unchanged.
2. Run Windows unit/local MQTT tests and the isolated network test. Confirm three identities, durable ACK behavior, duplicate and outage results. Verify the chosen Windows installation separately; Linux results do not prove PowerShell/device drivers.
3. Obtain Pi 4, adequate power supply/UPS, quality endurance SD/storage, three ESP32s, three correct PZEM-004T variants, secure enclosures and installation components selected by a qualified practitioner. Confirm component variants/interfaces before firmware/electrical work.
4. Have the adviser and qualified electrical practitioner review actual measurement/protection/isolation/earthing/enclosure arrangements and local requirements before installation in an occupied building. No automatic relay control is authorized by this gateway package.
5. Install supported 64-bit Pi OS Lite; verify Python version, patches, SSH, reserved LAN address, Ethernet/managed Wi-Fi, NTP, storage reserve and backups. Survey each floor's Wi-Fi coverage and interference under realistic conditions.
6. Install reviewed gateway version. Configure TLS certificates/expiry monitoring, Mosquitto unique credentials/ACL/session binding, private-LAN firewall restriction and no public port forwarding. Test credential rejection and room isolation; do not weaken TLS for a failed certificate.
7. Implement/review ESP32 firmware using the wire contract: real cumulative PZEM reads, stable event sequence/epoch, synchronized original timestamps, durable upstream journal, own-topic QoS 1/LWT/heartbeat, and application ACK after local Pi commit. Bench-test firmware journals/reboots with safe laboratory equipment.
8. Register actual website units/device identifiers; generate separate scoped API tokens securely; confirm tenant account isolation and applicable utility bill/class/period/validity. The PHP 14.74 owner reference alone is not billing authorization. Use a fresh real journal and `mode=real`; retain all test data outside production.
9. Commission **one room first** under qualified supervision. Compare actual meter measurements with a suitable reference; evaluate cumulative-counter scaling, precision, sample intervals and original timestamps. Check zero-cost initial baseline and each subsequent authorized interval transaction. A mock value or dashboard graph is not an accuracy result.
10. Interrupt Internet and restore it; restart ESP32/Pi/broker, test lost ACK, duplicate delivery, credential revocation/rotation, backlog order, NTP loss/jump, low storage and backup restoration. Verify no unacknowledged frame is discarded and no duplicate charge occurs. Do destructive hardware/storage tests on expendable laboratory copies before field use.
11. Add rooms 2 and 3 independently. Confirm each room's own sensor/token/topic/account and tenant-only view, concurrent uploads, freshness versus heartbeat, and blocked-room isolation. Compare manual/reference records and maintain an audit trail.
12. Run supervised field trials and document latency, loss/recovery, outage duration, power/storage behavior, Wi-Fi coverage, clock drift, electrical/measurement accuracy and billing reconciliation. Gather sufficient genuine hardware coverage before XGBoost training (existing requirement: 720 covered hourly observations). Keep synthetic test databases/models separate.
13. Establish operating responsibility for backups, SD/power faults, certificate/token renewal, account turnover, tariff validity and unresolved held readings. Future switching requires a separate reviewed control design and qualified approval; this installation stays monitoring only.

Physical sensor accuracy, Pi ARM performance/power-loss durability, firmware quality, multi-floor Wi-Fi reliability, occupied-building safety and real forecast performance cannot be verified without the assembled system and supervised trials. Do not describe software fixture test results as field measurements.
