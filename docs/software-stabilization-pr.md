# Integrate DormEnergy gateway and stabilize billing, recovery and forecasting

Device revocation and tenant termination could race with requests waiting for a billing lock, and the offline queue scanned whole room histories. This branch rechecks authorization after locking, validates exact stored measurement precision, batches dashboard lookups and uses indexed queue heads/neighbors. It includes the previously unmerged gateway integration and exact scoped receipt reconciliation, preserving account/ledger records, API field names and the existing design.

Forecast reports now include fixed-model rolling 1/6/12/24-hour endpoint/cumulative errors and baselines, explicit model-age policy and nonfinite rejection. Database/provider failure handling and affected runtime/build pins are hardened. No PostgreSQL schema change, production synthetic data, email sending, utility-rate approval, live secret change or automatic deployment is included.

Validation: 127 PostgreSQL backend tests + 68 gateway unit tests + one real-network integration test passed; portable backend 118 passed/9 PostgreSQL-only skips. The authenticated three-room MQTT/SQLite/verified-HTTPS/PostgreSQL run delivered 174 readings with 171 unique consumption charges, survived a 60-second cloud outage and actual gateway process kill, and ended with zero unresolved events/duplicate billing. Browser checks, supervised Render startup/restart, schema drift, disposable backup/restore, packaging and 35-package advisory checks are recorded in the reports.

Measured 5,000-row median queue claim improved from 14.439 to 0.027 ms, and dashboard query count from 17–19 to 11. Dashboard p95 increased in the short timing run; no production SLA is claimed. The changing synthetic occupancy forecast underperformed simple baselines; results are retained.
